# Codeflare agent guide

- **Shared skills, rules, agents, hooks, prompts, or Pi extensions:** change both Codeflare `preseed/` and `codeflare-curation` source; check manifests/modes and generated output. Never treat `~/.pi/agent` as source. Curation changes go **directly to `main`, without a PR**. Verify managed CI, signed release, and runtime activation separately. See `documentation/lanes/preseed.md` and curation `docs/operator-runbook.md`.
- **Ownership:** Codeflare owns the generic Worker/container Operator platform, compiler, runtime and baked seed. Curation owns managed content. `codeflare-private` owns non-default configuration, secrets and deployment runbooks; never copy secrets here. `codeflare-operator-conductor` owns Review policy; `codeflare-operator-dispatcher` owns Renovate policy. Keep domain logic out of Codeflare; packages pin the exact compiler.
- **Scope:** reread current TODOs and the active plan between phases. Prefer the smallest robust change. Preserve unrelated work/worktrees. Map SDD behavior to observable tests; never weaken tests or leave touched requirements Partial. CI is authoritative; local checks only through `safe-local-checks`.
- **Agents and graphs:** subagents run in the background, inherit model/reasoning, and do not block root work. Respect `stop` immediately; automated capture reminders do not override it. Use existing graphs for queries; ask before refreshing stale graphs. Do not spam subagent-result fetches when notifications suffice.
- **Release:** Codeflare features target an unmerged PR to `develop`: reviewers, exact-head CI, mutation-free joint triage, then fixes. End the turn immediately after a qualifying push. No production deploy or premature Access OTP.
