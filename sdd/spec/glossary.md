# Glossary

Canonical definitions for domain concepts. Use these terms consistently across all spec files, implementation, and documentation.

| Term | Definition |
|------|-----------|
| Session | A single working environment mapped to one container. Users can have multiple sessions. |
| Container | An isolated Cloudflare Container running a terminal server, agent CLI, and rclone sync. One per session. |
| Bucket | A per-user R2 storage bucket (`codeflare-{bucketName}`) holding all persistent files. |
| Agent | An AI coding CLI tool (Claude Code, Codex, Antigravity, Copilot, OpenCode, Pi, or plain bash). |
| Browser IDE | A per-session code-server editor served from the session container, isolated by session and available to advanced running sessions. |
| IDE agent | The editor-native integration matching the session's configured terminal agent: Codeflare in native Chat for Pi sessions, Anthropic's official Claude panel, or no extension for unsupported selections. Its conversation and process remain separate from the standalone Herdr runtime. |
| Editor activity | Any message sent from the Browser IDE to its session; each message refreshes the input-based idle timer without inspecting its content. |
| Session Mode | Standard (default) or Pro (advanced). Controls which preseed configs are deployed. |
| Preseed | Pre-configured rules, skills, agents, commands, and plugins deployed to a container on start. |
| Managed Resource Policy | Enterprise persistence mode for verified managed releases: `mutable`, `immutable` (exact managed/retired paths protected while personal resources persist), or `exclusive` (governed resource roots additionally reject personal persistence). |
| Managed Path Policy | Canonical `.codeflare/managed-paths.json` in the exact user bucket, derived and stamped by trusted reconciliation. Its digest/release/mode identity authorizes Worker enforcement; a container copy is non-authoritative filter input. |
| Tier | Subscription level (blocked, pending, free, trial, standard, advanced, max, unlimited/Custom). |
| Durable Object (DO) | Cloudflare's stateful compute primitive. Container DO manages per-session state; Timekeeper DO tracks per-user usage. |
| KV | Cloudflare Workers KV: settings, credentials, user records and preferences. It is not the authoritative session catalog or a lifecycle compatibility store. |
| D1 session catalog | Complete owner-scoped runtime session records, persisted lifecycle/generation/revision and conditional transition authority. Separate D1 history/report data does not become live quota authority. |
| Worker | The Cloudflare Worker running the Hono router - handles all HTTP/WebSocket requests. |
| Connect GitHub | An explicit action authorizing Codeflare to act as the user on GitHub (a GitHub App or OAuth App authorization). Never the Codeflare login. |
| GitHub App (user-to-server) | An internal GitHub App whose user-to-server token acts as the user, expires (~8h), and is refreshable; the EMU-reliable connect path. Distinct from installation/bot tokens, which are not used. |
| Egress injection | Replacing a container's placeholder credential with the real secret at the outbound HTTPS boundary (a Worker interceptor), so the real token never enters the container. Used for AI keys and, in enterprise, GitHub tokens. |
| DeployKeys | The per-user KV entry (`deploy-keys:<bucket>`) holding GitHub + Cloudflare deploy tokens. Configured AES-GCM encryption has an accepted plaintext JSON fallback when `ENCRYPTION_KEY` is absent; key identity is unchanged and rotation/migration remains unsupported. Ordinary non-enterprise user sessions receive real `GH_TOKEN`; enterprise and restricted Operator sessions receive a non-secret placeholder, with real-token injection scoped by the session binding (leakage-hygiene, not ordinary agent containment). |
| Browser Rendering token | A narrowly-scoped Cloudflare `Browser Rendering - Edit` API token used by the browser-run MCP servers and the Pi native browser extension. In enterprise mode it is configured admin-globally, stored encrypted, and retained Worker-side; the container receives only a non-secret `CLOUDFLARE_API_TOKEN` placeholder and interception injects the real token at the authorized account boundary. When absent the browser-run surface is not seeded. |
| GitHub Provider Config | The admin's Setup-wizard choice of GitHub provider (GitHub App or OAuth App) plus its client id (plain) and client secret (encrypted), stored in KV under `SETUP_KEYS.GITHUB_*` and resolved by `getGithubProvider` before any env-var fallback. Admin-gated in every mode (was enterprise-only) ([REQ-GITHUB-008](github.md#req-github-008-enterprise-github-provider-configuration-via-setup)). |
| Cloudflare OAuth Client | The operator's Cloudflare OAuth Application credentials (client id plain, client secret encrypted) set in the admin-gated Setup wizard under `SETUP_KEYS.CLOUDFLARE_OAUTH_CLIENT_*`, used by `CloudflareOAuthProvider` so each non-enterprise user connects their own Cloudflare account via OAuth (parallel to the GitHub Provider Config). Returns null in enterprise ([REQ-AGENT-064](agents.md#req-agent-064-connect-to-cloudflare-via-oauth)). |
| OAuth connect card | One shared, composable frontend component (`OAuthConnectCard`) that renders the GitHub/Cloudflare connect flow (tier selector → connect navigation → connected identity + account picker + disconnect), reused by the dashboard panel, Guided Setup, and the Settings accordion so connect behavior is defined once ([REQ-GITHUB-007](github.md#req-github-007-broaden-the-panel-gate-beyond-enterprise)). |
| Per-group dynamic routing | An enterprise mapping of Access groups to Dynamic Routes/native targets, default and reasoning (`SETUP_KEYS.GROUP_ROUTING`). Select the first configured matching group before eligibility filtering; empty/ineligible results never fall through. Unmatched users receive only an explicitly enabled, verified eligible fallback subset; absent configuration yields an empty catalog, never implicit global fallback or legacy-evidence migration ([REQ-ENTERPRISE-013](models-and-routing.md#req-enterprise-013-per-group-dynamic-routing)). |
| Admin Access Group | An enterprise Setup-configured Cloudflare Access group (`SETUP_KEYS.ENTERPRISE_ADMIN_ACCESS_GROUP`) whose members are granted admin (= Setup / user-administration) access, parallel to the email-based Admin Users list. Resolved live per-request in `requireAdmin` (never the hot auth path); elevation lives only on the request context. Distinct from the user-access groups — admin groups never participate in per-group routing ([REQ-ENTERPRISE-014](authentication.md#req-enterprise-014-admin-access-via-cloudflare-access-groups)). |
| Bisync | rclone's bidirectional sync mode - keeps container local files and R2 bucket in sync. |
| sleepAfter | Idle policy with new 1h/2h/4h/8h/12h options and retained legacy minute reads. Ordinary non-free default is 1h; ordinary free is 15m, while enterprise honors preference or 1h. Admin/dropdown eligibility is separate. Classified terminal input and each client-to-server IDE frame refresh it; reconnects/output do not. SDK idle sentinel is inert; final drains remain bounded and provider metering requires separate acceptance. |
| PTY | Pseudo-terminal - classic sessions use up to six outer PTYs; Herdr sessions use one outer client PTY and Herdr-owned inner PTYs. |
| Terminal Surface | The single xterm.js and outer PTY exposed by Codeflare for one backend Terminal session, using internal terminal ID `1`. |
| Terminal Mode | Immutable `classic` or `herdr` ownership stamped by the Worker when a session is created; missing or invalid historical values resolve to classic. |
| Herdr Runtime | The named in-container terminal multiplexer that owns tabs, panes, splits, workspaces, shells, and agents inside an opt-in Herdr Terminal session. Live processes are ephemeral; its official structural `session.json` snapshot persists under `.codeflare` for bounded recovery. |
| MultiView Layout | Codeflare's 2-split, 3-split, or 4-grid arrangement of terminal surfaces from distinct backend sessions. |
| CF Access | Cloudflare Access - external auth service used in default/onboarding modes. |
| Direct GitHub OAuth | Worker-managed GitHub OAuth flow used in SaaS mode when OAUTH_CLIENT_ID is configured. Completely separate from CF Access. |
| Timekeeper | Durable Object that tracks per-user compute usage for quota enforcement. |
| Setup Wizard | First-time configuration flow that provisions domain, auth, R2 credentials, and Turnstile. |
| SSE-C | Server-Side Encryption with Customer-provided keys: R2 encrypts each object with the deployment's `ENCRYPTION_KEY` (sent as `x-amz-server-side-encryption-customer-*` headers), so the bucket is opaque to plain R2-credential holders. On by default when the optional key is configured; Governed Mode disables it ([REQ-ENTERPRISE-018](storage.md#req-enterprise-018-governed-mode-toggle-and-configuration-surface)). |
| NDJSON | Newline-Delimited JSON - streaming response format used by the setup wizard |
| Circuit Breaker | Resilience pattern that stops calling a failing service after consecutive failures |
| SaaS Mode | Deployment mode (SAAS_MODE=active) enabling subscriptions, JIT provisioning, and usage tracking |
| Onboarding Mode | Deployment mode with public waitlist landing page (ONBOARDING_LANDING_PAGE=active) |
| Effective Tier | The billing-resolved subscription tier after applying grace periods and expiry rules |
| Fast Start | Container optimization that disables agent CLI auto-updaters to reduce startup time |
| Bisync Baseline | Initial rclone --resync state that establishes bidirectional sync tracking |
| Pre-warm | Pre-spawning a Terminal session's classic primary login shell or sole outer Herdr client before the terminal service is ready |
| Reconcile | Process of syncing preseed configs to match the current session mode (overwrite + cleanup) |
| BillingStatus | Subscription state: active, trialing, past_due, or canceled |
| Anti-flapping | Generation/revision-ordered D1 projections and generation/intent-fenced transitions prevent stale lifecycle evidence from replacing newer state. A transport close (including 4503) is not stopped authority; failed reads retain last ordered state |
| Rate Limiting | Request throttling keyed by user bucket identity, falling back to client IP (or anonymous key), within each limiter prefix. KV counters retain their initial `windowStart` until expiry, then reset; the per-isolate in-memory fallback uses the same anchored-window counting, not a sliding window |
| Webhook | HTTP callback from Stripe to the Worker for billing event processing |
| JWT | JSON Web Token - used for both CF Access (RS256) and GitHub OIDC (HMAC-SHA256) auth |
| HSTS | HTTP Strict-Transport-Security header enforcing HTTPS connections |
| CSP | Content-Security-Policy header restricting resource loading origins |
| Trivy | Container image vulnerability scanner run during CI deploy pipeline |
| Service Token | Secret-based auth for E2E tests and automation via X-Service-Auth header |
| Sync Daemon | Background process in entrypoint.sh running rclone bisync every 15 minutes; SIGUSR1 requests ordinary/final cycles, while SIGUSR2 is explicit cloud Sync-now recovery. |
| Sync-now | User-triggered manual sync action. Button in the storage browser ([REQ-STOR-015](storage.md#req-stor-015-explicit-sync-trigger-from-ui) AC1) sends SIGUSR2 to the sync daemon, fanning out to every session of the user's account ([REQ-STOR-015](storage.md#req-stor-015-explicit-sync-trigger-from-ui) AC2). One of three bisync triggers: 15-minute cadence, Sync-now, and final shutdown bisync. |
| Entrypoint | entrypoint.sh - container initialization script handling sync, config, and terminal server startup |
| Recovery Filter | Session-scoped rclone filter file (`/run/codeflare/sync/recovery-filters.txt`) that dynamically excludes transient files which vanish between listing and copy, preventing bisync fatal errors |
| Scoped R2 Token | Per-user R2 API token restricted to that user's bucket only |
| Spec Discipline | The universal SDD enforcement layer (`rules/spec-discipline.md`) inlined into every agent's instructions; activates only when `sdd/` exists in the project |
| Autonomy Mode | One of `interactive`, `auto`, or `unleashed` set in `sdd/spec/config.yml`; controls how aggressively spec-reviewer and doc-updater apply fixes without human confirmation |
| Enforce TDD | The SDD enforcement mode set via `enforce_tdd: true` in `sdd/spec/config.yml` (default true); requires scoped per-AC observable assertion coverage, resolving `@test` parity with `@impl`, or legitimate manual methods for manual ACs. Mentioning a REQ ID or linking a method is not coverage or execution evidence. Coverage defects can demote Implemented to Partial outside import transition; transition suppresses that demotion, not source-truth checking. Review runs use their actual trigger/scope, not universal test execution on every push. Manual opt-out remains available; unleashed refuses `enforce_tdd: false`. |
| Import Mode | The `/sdd init` mode that activates when an existing codebase is detected; derives a spec from observed code behavior instead of bootstrapping from prose |
| Vault Encryption Key | A bucket-stable 32-byte key derived in the Worker from the configured master secret and bucket identity using HKDF-SHA256. It protects SilverBullet's browser-local cache, not container plaintext or R2 objects. Session deletion does not rotate this identity; it does not provide per-session forward secrecy. See [REQ-VAULT-021](vault.md#req-vault-021-bucket-stable-vault-url-and-bucket-derived-key). |
| Strict Gateway Egress | An optional, enterprise-gated, default-OFF setup-wizard toggle (`setup:strict_egress`) that forces the container's direct-internet HTTP/HTTPS (and WebSocket) egress through the Workers VPC `EGRESS` binding and the customer's Cloudflare Gateway; only this deployment's own-account destinations (its R2 + account-scoped CF API / Browser Rendering) are exempt and egress direct, while any other account's host rides the Gateway ([AD86](../../documentation/decisions/README.md#ad86-platform-native-cloudflare-primitives-bypass-strict-gateway-egress-only-direct-internet-egress-takes-cf1network)). Fails closed (503 `EGRESS_UNAVAILABLE`) when the binding is unbound, byte-identical to today when OFF ([REQ-ENTERPRISE-016](security.md#req-enterprise-016-strict-gateway-egress)). |
| EgressController | Strict Gateway Egress catch-all. It transparently sends direct-internet hosts through `env.EGRESS.fetch`, keeps this deployment's account-scoped Cloudflare API direct, and accepts only the session's bound bucket on own-account R2. R2 requests are re-signed with that user's Worker-held bucket-scoped credential while the container holds only a placeholder; another bucket or missing scoped credential fails closed. It bridges WebSocket upgrades, reads resolved state from `ctx.props`, and performs no per-request KV read ([REQ-ENTERPRISE-016](security.md#req-enterprise-016-strict-gateway-egress)). |
| AI Gateway config (wizard) | The customer's AI Gateway URL + token resolved by `getAigConfig(env)` wizard-first (KV `setup:aig_gateway_url` plain, `setup:aig_token` encrypted) with the deploy-time `AIG_GATEWAY_URL`/`AIG_TOKEN` secrets as a per-field fallback; resolved once Worker-side and passed to the `LlmInterceptor` via props, never entering the container ([REQ-ENTERPRISE-017](setup.md#req-enterprise-017-ai-gateway-configured-in-the-setup-wizard)). |
| EGRESS binding | The Workers VPC `[[vpc_networks]]` Fetcher binding (`binding="EGRESS"`, `network_id="cf1:network"`) that routes container egress through the customer's Cloudflare Gateway; enterprise-only, committed commented-out in `wrangler.toml` and injected at deploy time by `deploy.yml` when `ENTERPRISE_MODE=active` ([REQ-ENTERPRISE-016](security.md#req-enterprise-016-strict-gateway-egress)). |
| Cloudflare Gateway | The customer's Zero Trust (Secure Web) Gateway whose existing egress traffic policies (allow/block/isolate/DLP) apply to traffic leaving over `cf1:network` when Strict Gateway Egress is ON; codeflare inherits but never creates or modifies them ([REQ-ENTERPRISE-016](security.md#req-enterprise-016-strict-gateway-egress)). |
| Cloudflare Mesh | The reserved Cloudflare network (id `cf1:network`) backing the Workers VPC `EGRESS` binding; container public egress rides it through the customer's Cloudflare Gateway. The binding is enterprise-only and injected at deploy time ([REQ-ENTERPRISE-016](security.md#req-enterprise-016-strict-gateway-egress)). |
| Workers VPC | Cloudflare's Workers VPC / Connectivity Directory capability that exposes a private network — a single Cloudflare Tunnel, or all of Cloudflare Mesh via `cf1:network` — to a Worker as a Fetcher binding; the transport behind the `EGRESS` binding ([REQ-ENTERPRISE-016](security.md#req-enterprise-016-strict-gateway-egress)). |
| Governed Mode | The enterprise-only, deployment-wide, default-OFF policy (`SETUP_KEYS.R2_SSE_DISABLED`) that disables R2 SSE-C so corporate-owned bucket data is readable/scannable by the company's security tooling ([REQ-ENTERPRISE-018](storage.md#req-enterprise-018-governed-mode-toggle-and-configuration-surface)). Flipping it losslessly re-encrypts each bucket in the background, driven by the separate ancillary/slower/event-driven owner, not frequent batch-status (never at session start — D1 ownership gates migration and session `/start` is gated `409` while a bucket is migrating); only the R2 SSE-C path is affected (vault + secret-at-rest crypto unchanged) ([REQ-ENTERPRISE-020](storage.md#req-enterprise-020-governed-mode-re-encrypt-migration-engine), [REQ-ENTERPRISE-021](storage.md#req-enterprise-021-governed-mode-migration-safety-and-access-boundary)). |
| R2 regime state | The per-bucket `r2-regime:<bucket>` KV state object (`{status: ready\|migrating\|mixed-recovery, regime, from?, to?, generation, cursor?, phase?, drained?, leaseExpiresAt?, keyMd5?, stuckCount?, lastFailedKey?}`) — the single source of truth for a bucket's encryption regime and any in-flight migration. Replaces the old boolean `UserPreferences.r2SseRegime` marker + standalone migration lock (a boolean cannot describe a partially in-place-migrated bucket). Every R2 header choice keys off the committed `regime` (not the raw policy); the regime advances only after a verified re-encrypt pass ([REQ-ENTERPRISE-020](storage.md#req-enterprise-020-governed-mode-re-encrypt-migration-engine)). |
| Lossless re-encrypt migration | Switching a bucket between SSE-C and plaintext by an in-place same-key server-side `CopyObject` per object with `MetadataDirective=REPLACE` (R2 rejects `COPY` on a self-copy; source HEAD metadata + `copy-source-if-match` are re-supplied; copy-source SSE-C decrypts the source, dest SSE-C encrypts the target), idempotent/resumable via a target-regime HEAD probe — never a nuke. Runs chunked through the ancillary/slower/event-driven owner, not frequent `batch-status` or session start; D1 ownership gates the work, and verification precedes regime commit. This SSE-regime copy does not rotate the immutable deployment key; deployment-key rotation remains unsupported ([REQ-ENTERPRISE-020](storage.md#req-enterprise-020-governed-mode-re-encrypt-migration-engine)). |
| Preseed bake | The agent seed materialized into an on-disk file tree baked into the container image (from the committed `agent-seed.generated.ts`, byte-identical to `getConfigsForMode(mode, false)`). In Governed Mode it is laid down locally before the initial sync so the `--checksum` sync skips the unchanged seed and transfers only user deltas ([REQ-STOR-017](storage.md#req-stor-017-faster-startup-sync--bisync-head-storm-fix--governed-mode-preseed-bake)). |
