# Spec Changes

Semantic changes to the specification. Git history captures diffs; this file captures intent.

## 2026-07-25

- **Claude's pull-request reviewers now work from a scoped evidence packet instead of scanning the repository** ([REQ-AGENT-086](agents.md#req-agent-086-claude-reviewer-direct-evidence-and-root-handoff) AC1 rewritten, AC2 narrowed, AC7 and AC8 added; stays Implemented). Each lane cost 93,000 to 103,000 tokens per round and barely varied with how much had changed — a two-file comment-only round cost 83% of an eight-file one — because the reviewers pulled evidence by searching the whole repository and reading what came back. They now build their lane packet once through the shared builder and reason from its hunks and exact changed-input ranges, following a cross-lane path only where a resolved symbol actually overlaps a changed hunk rather than wherever a filename matches. With that transport in place the tools it replaces are gone: repository-wide search, indexed retrieval, graph traversal, and file mutation. Two capabilities were deliberately kept because nothing in a shell replaces them — bounded file reading, and the lookup of prior-session user preferences that lets a reviewer drop a finding the user already ruled on. Removing the write tools also settles a contradiction the definitions had carried for some time: they described writing files while their own exit checklists required that no file be written. An earlier attempt to slim these reviewers was reverted for tripling review cost; it removed the retrieval transport without putting one back, which is why this change adds the packet first and only then takes the scanning tools away. The reduced toolset applies to `/review` as well, which runs the same two agents in five places; the graph-heavy work there belongs to a separate agent that keeps every tool it had.

- **The review evidence packet builder is now one shared program instead of a Pi-owned one** ([REQ-AGENT-085](agents.md#req-agent-085-pi-reviewer-direct-evidence-transport) implementation anchors repointed and one constraint added; [REQ-AGENT-059](agents.md#req-agent-059-pi-native-review-findings-handoff) anchors repointed; both stay Implemented, no acceptance criterion changed). The program that resolves a review lane's changed files, its hunks with exact old and new line ranges, and the cross-lane inputs those hunks invalidate lived in the Pi tree, so only Pi could use it. Nothing in it is Pi-specific — it reads Git and emits JSON — and it is the transport that lets a reviewer work from scoped evidence instead of pulling raw scan output into its context. It now lives in the canonical tree and reaches every runtime through the ordinary seed transform, including Pi, at the same path Pi's own scope skill already invokes. Pi's scope skill itself is unchanged and still overrides the canonical one. A test pins that Pi's copy is byte-identical to the source, because skill adaptation computes its runtime-name rewrites before it decides a file is not prose, and because Pi's manifest no longer owns the file the previous identity check no longer sees it.

- **A rule that is renamed or merged can no longer leak into Pi's instructions unnoticed** ([REQ-AGENT-014](agents.md#req-agent-014-manifest-driven-preseed-pipeline) AC8 added, Implemented). Three collections in the seed generator name Claude rules by exact path in order to *exclude* them from Pi — some because the compact Pi constitution already carries their policy, some because a skill owns them, some because they become on-demand skills. Only one of the three validated its keys. For the other two, a renamed or merged rule left a key pointing at nothing, and the failure was both silent and inverted: the rule stopped being excluded and flowed into Pi's instruction file, which is the opposite of what the collection exists to do, with no error anywhere and no test that could see it. All three collections are now checked against the Claude source set before anything is generated, and a key that resolves to nothing fails the build while naming both the missing rule and the collection holding the dead key. Directory-shaped keys match by prefix, mirroring the lookup they already drive.

- **A review now covers the push that triggered it, instead of the one before** (no acceptance criterion changed; regression tests in `host/__tests__/git-push-review-reminder.test.js`). GitHub's pull-request metadata lags its own ref update, so a `gh pr view` issued milliseconds after a successful push can still report the previous head. That head became the right-hand side of the incremental review range, which meant the directive named a range ending one commit *before* the push that fired it — a delta already reviewed — while the newly pushed commit went unreviewed for that round. The hook now resolves the pull-request head and the local head separately and prefers the local one, but only when it provably contains what GitHub reported, so the range can widen and never narrow. Every other relationship keeps GitHub's value: a push of a non-current refspec, a push the remote rejected, and a concurrent push from elsewhere all leave the local head potentially *behind* the pull request, and reviewing those against a local range would silently drop commits. The turn-end enforcement hook deliberately keeps reading GitHub's head, because that is the value its acknowledgement file is compared against.

- **Opening the editor before it is ready now shows a page that eventually admits defeat** ([REQ-IDE-003](browser-ide.md#req-ide-003-ide-lifecycle-and-availability) AC3 amended, Implemented). A freshly opened IDE tab can wait on two different things, and both were mishandled. Waiting for the container to become healthy produced a JSON error body, which a bare `_blank` tab renders as raw machine text — the in-container warming page never got the chance to answer, because the Worker's health probe rejects the request before it can be forwarded. Waiting for the editor to bind inside a healthy container did show a page, but one that meta-refreshed every two seconds indefinitely, presenting a supervisor that will never arm as mere slowness. Both waits now serve an HTML page that reports elapsed time and stops with a failure state — the container-side one on a module-level clock, the Worker-side one on the episode start carried in the query string, stripped before the base-path-native server ever sees it and redirected back out of the tab's address bar once the container answers — a tab left sitting on an exhausted start would otherwise render the give-up page instantly on every later reload, a permanent failure state its own "reload to try again" could not escape. The Worker side carries a start rather than an attempt count because each attempt also pays a container health probe of unpredictable length, so an attempt count multiplied by the refresh interval reported a wait shorter than the one that had actually passed, and bounded a number of tries rather than a duration.

- **A long IDE chat no longer forgets what you just said** ([REQ-IDE-006](browser-ide.md#req-ide-006-ide-conversation-context-and-credential-isolation) AC5 added, Partial — unchanged by this entry, AC2 still awaits deployed Claude evidence). Each native Pi request rebuilds its prompt from scratch and replays the earlier conversation into it under a byte budget. That budget was spent starting from the *first* turn, so once a conversation outgrew it the replay carried the opening turns and was cut off before reaching the newest — the agent answered without ever seeing the message just sent, and nothing surfaced the loss. The replay is now filled from the newest turn backwards and restored to conversation order, and the budget rose from 64 KiB inside a 512 KiB envelope to 512 KiB inside 1 MiB. The transport allows 4 MiB per JSONL line, so the remaining headroom absorbs JSON escaping; past that the binding limit is the model's own context window rather than anything Codeflare sets. Because each section is measured before JSON escaping and the envelope only after it, a prompt can still overflow with every sub-budget respected; that case now discards whole units — references, then diagnostics, then open files, then the replay shrinks and finally goes — instead of clamping the rendered string and handing the model a context object cut off mid-structure. The active editor is kept longest, because a turn that says "fix the selected code" is answerable without the older turns and unanswerable without the selection. That whole policy is now its own acceptance criterion rather than a clause bolted onto the bounded-context one.

- **A deploy run now says which environment it targeted, and concurrent dispatches no longer cancel each other's verification** ([REQ-OPS-026](operations.md#req-ops-026-concurrent-deploy-dispatches-are-legible-and-independently-verified), new, Implemented). The deploy workflow's `run-name` resolves the dispatched environment into the run title, so the Actions list answers "what did this deploy to?" without opening the run. The inline `verify` job now passes its own run id to the reusable PR Checks workflow as a concurrency discriminator: a called workflow inherits the *caller's* concurrency context, so two environment deploys dispatched off one branch previously landed in the same group and the second cancelled the first — surfacing as a cancelled run that deployed nothing, with a green commit reading as unverified.

- **Container-start settings and plugin assembly is now its own requirement** ([REQ-AGENT-099](agents.md#req-agent-099-agent-settings-and-plugins-assembled-at-container-start), new, Implemented; [REQ-AGENT-008](agents.md#req-agent-008-preseed-deployed-to-container-on-start) narrowed to its first two acceptance criteria). REQ-AGENT-008 had accumulated two operationally distinct sub-jobs behind one title: getting preseed files onto disk (R2 seed plus the initial sync down, `src/lib/r2-seed.ts`) and assembling `settings.json` and the plugin configuration from them (`entrypoint.sh`). The second set moves out unchanged — the hooks-aware merge, the Pro-mode hook registrations, permanent plugin enablement, the three file-state cases, and the agent-view setting are now REQ-AGENT-099 AC1 - AC5, carrying their own constraints (plugin permanence, the managed-hook namespace prefix, the detector as single source of truth). REQ-AGENT-008 keeps the sync-before-baseline ordering constraint, and every dependency pointing at it still means file delivery, so no inbound reference changed meaning. Two of the moved criteria also gained honest verification: plugin enablement and the three settings-file cases were anchored to an R2-seeding test that could not observe either, and now point at the entrypoint tests that execute the shell — which is also why the three-cases criterion no longer claims manual verification.

- **Background agents no longer take over the terminal with the full-screen agent view** ([REQ-AGENT-099](agents.md#req-agent-099-agent-settings-and-plugins-assembled-at-container-start) AC5, Implemented). Both session-mode `SETTINGS_CONFIG` literals now set `disableAgentView`, so the agent view's dispatch input and session switcher can no longer replace the terminal — its swipe navigation made Claude Code unusable on a phone. The setting also gates the agent-listing command (`claude agents --json`), which refuses to run while it is set (upstream behaviour, verified against Claude Code 2.1.219 on 2026-07-25).

- **The Browser IDE now opens its workspace without a trust prompt or an extension-recommendation prompt, for every agent kind** ([REQ-IDE-009](browser-ide.md#req-ide-009-frictionless-workspace-open-for-every-ide-agent), new, Implemented; [AD114](../../documentation/decisions/README.md#ad114-native-pi-chat-and-the-official-claude-extension-own-editor-integration) amended). A kind-independent base settings seed disables workspace trust (`security.workspace.trust.enabled: false`) and ignores extension recommendations (`extensions.ignoreRecommendations: true`) for Pi, Claude, and the empty inventory. The previously Claude-only OpenVSCode User-settings seed now runs for every kind — Pi and the empty inventory receive the base settings alone, Claude receives them merged with its isolated config — and a preparation failure still fails closed and refuses the launch. Disabling workspace trust is consistent with the container-is-the-boundary posture ([REQ-IDE-007](browser-ide.md#req-ide-007-ide-guarded-approval)) because IDE agents already run unrestricted.

## 2026-07-20

- **Every test suite runs sharded through one gated action** ([REQ-OPS-003](operations.md#req-ops-003-pr-checks-run-lint-test-typecheck-and-security-audit); Implemented). The frontend suite is sharded and gated on its JSON report like the backend already was, instead of being one unshielded `npm test`, and the completeness reconciliation now covers every suite rather than the backend alone.

- **The backend suite runs in parallel and shard coverage is reconciled** ([REQ-OPS-003](operations.md#req-ops-003-pr-checks-run-lint-test-typecheck-and-security-audit); Implemented). The Workers pool no longer runs one test file at a time, and the aggregate job now fails when a backend test file present in the tree ran in no shard — the hole that serialization was never actually closing.

- **actionlint's version pin is bumped automatically** ([REQ-OPS-020](operations.md#req-ops-020-shadow-pin-version-bump-automation), [REQ-OPS-021](operations.md#req-ops-021-workflow-file-static-analysis); Implemented). The checksum-pinned actionlint binary is a shadow pin Dependabot cannot see; its weekly bump PR resolves and re-verifies the new checksum, so it needs no manual checksum step.

- **The workflow static-analysis audit now blocks merges** ([REQ-OPS-021](operations.md#req-ops-021-workflow-file-static-analysis); Implemented). zizmor and actionlint findings against workflow files fail the required `test` status context instead of only being recorded as advisory SARIF alerts, so a workflow defect can no longer merge on the strength of an alert nobody read.

- **CI checks run as parallel lanes and deploys reuse unchanged container images** ([REQ-OPS-001](operations.md#req-ops-001-deploy-workflow-trigger-and-pre-deploy-pipeline), [REQ-OPS-002](operations.md#req-ops-002-docker-image-build-vulnerability-scan-and-registry-push), [REQ-OPS-003](operations.md#req-ops-003-pr-checks-run-lint-test-typecheck-and-security-audit), [REQ-OPS-013](operations.md#req-ops-013-deploy-command-and-post-deploy-hooks), [REQ-SEC-011](security.md#req-sec-011-container-image-scanned-for-cves-before-deploy); all stay Implemented). PR checks run as parallel path-filtered lanes with a fail-closed backend test gate instead of one serial job, and deploys reuse the already-scanned container image when nothing it depends on changed, cutting typical pipeline time (per [AD112](../../documentation/decisions/README.md#ad112-ci-runs-as-parallel-path-filtered-lanes-and-deploys-reuse-content-addressed-container-images)).

- **Scripted e2e suite removed** (REQ-OPS-004 and REQ-OPS-015 deleted from `operations.md`). The dispatch-only e2e layer could report green with zero executed tests and is replaced by the unit suites plus the k6 stress suites, which remain; [REQ-AUTH-004](authentication.md#req-auth-004-service-token-authentication-for-service-automation) is retitled from "E2E testing" to "service automation" to match its surviving consumers.

- **PR checks also run nightly** ([REQ-OPS-003](operations.md#req-ops-003-pr-checks-run-lint-test-typecheck-and-security-audit); Implemented). The full PR-check lane matrix now runs unconditionally once a night in addition to every pull request and manual dispatch, catching flaky tests and dependency drift between pushes.

- **Workflow-file static analysis specced** ([REQ-OPS-021](operations.md#req-ops-021-workflow-file-static-analysis); new, Implemented). The zizmor security audit and a new checksum-pinned actionlint check now have REQ coverage; both are informational, with merges still gated by the `test` status context.
