- **One refused lane spawn no longer waves its siblings through the triage gate** ([REQ-AGENT-104](agents.md#req-agent-104-review-acknowledgement-requires-a-published-verdict) AC7 unchanged; behavioral fix). Three lane spawns issued as one batch got two different answers: the first was refused and the other two launched. The gate reads each lane's newest spawn record and treats one with no completion as a lane still in flight — the escape that stops it blocking a round genuinely running. But a refused call still leaves its `tool_use` record behind, and that record never completes, so refusing the first call of a batch wrote the very evidence that classified the lane as in flight and let the siblings through a second later. Replaying the recorded transcript isolated the sequence exactly: the refusal was decided before the batch's spawn records were flushed, and both later calls saw the refused record. It is not only a batch effect — that record stays newest for the rest of the round, so one refusal reopens the gate until another spawn lands. Each lane now walks back to its newest spawn that actually reported a completion, and only a lane that has never once completed counts as in flight, so a refused or user-rejected record is skipped rather than trusted while a first round still running keeps its escape. A row pins the batch, which is the oracle: the sibling calls see the refused record and must still get the answer the first call got. Verified against the recorded batch (three refusals where there had been one refusal and two launches) and against the six gate states already pinned, which are unchanged either way.

- **The capture request travels in the prompt instead of as a path to itself** ([REQ-MEM-020](memory.md#req-mem-020-capture-requests-are-re-delivered-under-a-bound-and-committed-only-against-an-artifact) unchanged; behavioral fix). Raising the turn budget did not make a large window capturable, so the run was traced: the launcher built a self-contained 83KB request and then handed the model its *path*, which put the retrieval on the tool-result channel. That channel cannot carry a transcript — the harness persisted the output and returned a 2KB preview — so the agent spent every turn paging its own payload back in (`cat`, `Read`, `python3 -c print()`, then two offset reads of the persisted file) and hit the ceiling as it began writing the note. No budget fixes that; each extra turn buys one more page. The request is now rendered inline into the prompt, metadata and delimited transcript together, so the conversation is in context before the first turn and the first Bash call is the write. This is what Pi's contract has always required ("VARS_FILE contains the transcript inline; there is no INPUT_FILE or separate transcript file") and what this script's own comments already claimed; Pi's larger 200,000-char budget shows size was never the discriminator. The capture contract drops the evidence-read step it could not perform, and the test row asserting the model receives a path — which pinned the defect in place — now asserts it receives the conversation. Verified live against the exact window that had failed eight consecutive times: it published on the first attempt, the counter advanced, and the graph chunk merged. Inlining also makes the frame forgeable in a way a JSON string value was not — a captured line reading `--- END TRANSCRIPT ---` followed by instructions would close the launcher's own frame, and the capture holds `Write` and `Bash` under bypassed permissions — so the delimiters carry a per-run marker drawn from `/dev/urandom`, and the contract states that everything inside them is conversation data rather than instruction and that output paths come from `capture_file` alone. The `Read` tool is withdrawn along with the retrieval it existed for, verified by a live run that writes and publishes without it. The shipped `memory-capture` agent definition is brought to the same contract — six turns, the inline request, and no grant of the `Read`, `Grep` and `Glob` tools whose retrieval and filesystem search the contract no longer has a use for — because it regenerates into the seed alongside the runner and otherwise ships as a standing instruction to fetch the path this change exists to remove. The fail-closed refusal is the security-load-bearing half of the frame, so it gains a row of its own: both draws are broken, the run must exit without starting the model, and it is paired against an identical fixture that draws normally, because the exit status proves nothing on its own — the healthy run exits 3 too, from the publisher. Review then caught that the guard was measuring the wrong quantity: `capframe` is eight constant characters of the fallback's own template, so an `mktemp` that echoes the template unexpanded returns twenty entirely predictable characters and passes a length test meant to establish entropy. Replayed against the pre-fix script it started the model on `--- BEGIN TRANSCRIPT capframeXXXXXXXXXXXX ---`, which is the refusal failing open in the one case it exists for. The fallback now strips its constant prefix and rejects a remainder still carrying the template's X's, so the length test measures what was actually drawn, and a second row pins the harder case where `mktemp` succeeds rather than fails.

- **The capture turn budget goes from four to six** ([REQ-MEM-020](memory.md#req-mem-020-capture-requests-are-re-delivered-under-a-bound-and-committed-only-against-an-artifact) Constraints updated, no AC change; [AD124](../../documentation/decisions/README.md#ad124-bounded-re-delivery-replaces-the-memory-capture-hard-block) amended). - **A shell string is parsed as code, so `bash -c "git push"` no longer walks the triage gate** ([REQ-AGENT-104](agents.md#req-agent-104-review-acknowledgement-requires-a-published-verdict) AC7 unchanged; remains Implemented). The wrapper list handled every form that passes a delivery as a *command* — `sudo`, `env`, `nice`, `timeout`, `xargs`, a path-invoked binary. A shell does something different: it takes the delivery as a *string* and runs it as code. The parser saw `bash`, found it neither a tool nor a known wrapper, set command position false, and dropped every remaining word — including the one holding the push. `bash -c`, `sh -c`, `zsh -c`, combined forms like `-lc`, and `eval` all returned "no git ran here", verified before the fix and again after. The window this gate exists to hold was open for any of them, and this was a regression the gate's own rewrite introduced: before it, all Bash was refused outright while a round awaited its table, so nothing needed parsing to be caught. Shells now descend into their `-c` argument, and `eval` joins its remaining words so both `eval "git push"` and `eval git push` resolve. A bare word under a shell with no `-c` is a script file, whose contents are not in the command, so it stays unread rather than guessed at — which is also what keeps `bash run-review-lane.sh` classified exactly as before. A herestring is code by the same reasoning and is read the same way, glued form (`bash <<<"git push"`) included, since `<` does not break a word here. Two forms stay unread on purpose and are recorded as a known limit rather than patched: a heredoc fed to a shell, because the same body is data when written to a file and code only when fed to a shell and `stripHeredocs` discards the association that tells them apart; and a shell fed over a pipe, whose code is not among its own words and which would need a "could not read this" return value in a contract the Stop path shares, where a false positive means reporting a delivery that never happened.

The byte-identity guard that covers the other two covers this as well: skill adaptation computes the Pi runtime rewrites before it decides a file is not a `SKILL.md`, so an executable in that tree is in scope for them and a future comment naming a rewritten runtime would silently corrupt Pi's copy.

- **The evidence resolver was padding the prompt it exists to shrink** ([REQ-AGENT-105](agents.md#req-agent-105-review-lane-turn-economy) constraints trimmed to their boundary statements). Its first live round cut the code lane from eleven turns to two and the documentation lane from thirteen to seven, and the same round found five defects in it. The caller-impact scan matched any declaration-shaped line, so it harvested `r`, `x`, `and` and `git` as symbols and searched the whole repository for each, pushing thousands of tokens of workflow YAML into every prompt; it now requires a top-level declaration in a code path and discards a name too common to be a caller signal. Reference resolution counted any occurrence anywhere, so a symbol surviving only as a YAML comment read as live - a false clean in the one check whose job is spotting the reference that no longer resolves, and the direction the module header promises never to fail in. An anchor target is text from the branch under review and could name a path outside the repository. The resolver is now time-bounded, and the branch that produced the worst of these had shipped with no test at all.

- **The lane prompt moved to standard input** ([REQ-AGENT-105](agents.md#req-agent-105-review-lane-turn-economy) constraint added). Linux caps a single argument at 128 KB no matter how much larger the total argument limit is, and the prompt was passed as one. The blocks inlined into it are deliberately larger than that - the packet cap alone is 128 KB - so the first round carrying packet, triage and evidence together killed the code lane with `Argument list too long` before it reached the model. The ceiling is removed rather than tuned under, because tuning the caps down would have traded away the evidence that removes turns to fit a limit that need not apply.

- **Lanes now receive the answers their checklists used to send them looking for** ([REQ-AGENT-105](agents.md#req-agent-105-review-lane-turn-economy) AC7 and three constraints added). Triage removed the six startup calls and the packet removed the diff rebuild, but neither touched the lookups the lane documents mandate, and those turned out to be what the turn count is made of: a documentation lane whose entire ownership was one table cell still spent thirteen turns confirming an index existed, probing a layout, resolving every reference to real code, verifying every anchor and checking the decision record. None of that scales with the diff and all of it is grep. It is now resolved before the lane starts. The reciprocal half is the one that was missing for longer: describing waves while handing over a checklist that says go and look does not produce waves, so broad discovery, indexed search, re-reads and re-derivation are now forbidden outright, which is the discipline the Pi reviewers have always run.

- **All three Claude reviewers now pin `medium` effort** ([REQ-AGENT-086](agents.md#req-agent-086-claude-reviewer-direct-evidence-and-root-handoff) AC6 rewritten). Reasoning tokens are output tokens, and the code lane was the largest output producer of the three by a wide margin while pinned `high`. The pin dropped to `medium` in the frontmatter without AC6 or its value-form anchor moving with it, which left the specification asserting a pin the code did not carry and would have failed the seeded-effort test outright - the anchor form that names a value is exactly what catches that, and it did.

- **A lane at its round limit now costs nothing in Pi too** ([REQ-AGENT-040](agents.md#req-agent-040-pr-boundary-lane-classification-and-agent-dispatch) AC8 added). Both runtimes already declined a lane that owned no changed file, and Pi already declined one suspended by an SDD transition, but neither had the third no-op its own lane documents define: five rounds already spent on that surface. Pi therefore paid a full agent startup to be told what six lines of git log answer. The two runtimes reach that at different points and the AC says so: Claude still demands the lane and its runner short-circuits before invoking a model, while Pi drops it at classification. Both cost zero model tokens, which is what the AC states; pinning the mechanism would have been a false claim about Claude. The counter is deliberately asymmetric between the two lanes - spec-reviewer counts a subject that contains its tags, doc-updater one that starts with them - because that is what each lane document says, and unifying it would silently move when a limit fires.

- **Shedding a field without telling the lane costs the turn it was meant to save** ([REQ-AGENT-105](agents.md#req-agent-105-review-lane-turn-economy) constraints added). Degrading an over-cap packet by dropping `patch` was measured immediately: the very review round that shipped it received `patchOmitted: true`, had no contract for what that meant, and spent a wave rebuilding the hunks with its own `git diff` - thirteen turns where the previous round took eight. A shed field is now a named marker with a stated recovery, in the same section that defines the packet. Report length joined the contract at the same time, because output is the most expensive thing a lane emits and the lanes were narrating their searches back: a finding is bounded, a clean pass is a count in its manifest row, and no lane recaps its own instructions.

- **The gate demanded lanes without telling them what to review** ([REQ-AGENT-105](agents.md#req-agent-105-review-lane-turn-economy) AC4-AC5 added). The push nudge always passed a range; the Stop hook's demand never did. Both the inlined packet and the zero-token ownership short-circuit are conditional on having a range, so a demanded lane received neither and was told to review the entire PR diff instead of the increment - the raw-scan blowup the packet exists to prevent, on the path every re-demand, every failed-lane retry and every post-compaction spawn takes. The demand now resolves the same range under the same ancestry guard as the nudge. Relatedly, evidence over its byte cap was dropped whole, which returned the lane to the six-call Phase 0 the block replaced; it now sheds the one field that blew the cap and keeps the answers.

- **The verdict demand shared the lane demand's rate limiter** ([REQ-AGENT-104](agents.md#req-agent-104-review-acknowledgement-requires-a-published-verdict) constraint added). The escape hatch was given its own counter and then read the old one anyway, so a head that spent its budget merely getting the lanes launched was acknowledged on the second pass with no verdict ever demanded - and the demand that would have been answered exited silently, because the shared breaker had already tripped. Each demand now counts on its own file and trips its own breaker. The regression test seeds one counter and asserts on the other; driving both from zero moves them in lockstep and passes either way, which is why the first attempt shipped inert.

- **Triage defaults and inlined-block size are now specified, not just implemented** ([REQ-AGENT-103](agents.md#req-agent-103-deterministic-lane-triage) AC5 and a byte-cap constraint added). Two behaviours were shipped and tested with nothing in the spec to hold them: a config that never mentions `enforce_tdd` resolves to on rather than to a silent opt-out - the earlier reading turned a missing key into an affirmative false, which is fail-open in an enforcement gate - and the packet and triage blocks inlined into a lane's prompt are byte-capped so an oversized block degrades to a normal review instead of a skipped one.

- **Review cost is a turn problem, and lanes now gather evidence in waves** ([REQ-AGENT-105](agents.md#req-agent-105-review-lane-turn-economy), new, Implemented; rationale and the measured model in [AD117](../../documentation/decisions/README.md#ad117-review-lane-cost-is-governed-by-turn-count-so-evidence-gathering-is-structured-in-waves)). Four rounds of measurement refused to correlate with diff size - two commits cost 1.30M prompt tokens where nine cost 0.80M - because a lane re-sends its whole prompt every turn, making cost grow with the square of the turn count. Every lever tried before this was linear in turns and worth a tenth of what the quadratic one is. Lanes now work in waves that each ask everything outstanding at once, and the same measurement settles what to embed: small always-applicable policy is carried, large conditional policy is read inside a wave that was happening anyway, because a fetch only costs a turn when it gets a turn to itself.

- **Inlining every sub-policy was measured and reversed** ([REQ-AGENT-104](agents.md#req-agent-104-review-acknowledgement-requires-a-published-verdict) constraint removed; the surviving rule is [REQ-AGENT-105](agents.md#req-agent-105-review-lane-turn-economy) AC2-AC3). The argument for embedding was that a fetch costs its bytes plus a turn while an embed costs only its bytes. The prediction was wrong in the direction that matters: carrying 41 KB of conditional policy took the spec lane from 10 turns to 16 and its cost from 466k to 1,117k prompt tokens, because embedded bytes are re-sent on every turn while a fetch inside a wave that was already happening costs no extra turn at all. The rule that replaces it is sized by turn cost rather than byte cost - embed what is small and unconditional, fetch what is large and conditional, and never on a turn of its own.

- **The verdict requirement now holds on every acknowledgement path** ([REQ-AGENT-104](agents.md#req-agent-104-review-acknowledgement-requires-a-published-verdict) AC5-AC6 added; regression tests in `host/__tests__/enforce-review-spawn.test.js`). Two defects in the first cut: a second, older scan acknowledged a head on lane exit alone and returned before the new gate ran, so the fix directive never fired; and the check matched the table's header and divider anywhere in a message, which the gate's own demand text contains - so restating the required format would have acknowledged a head with no verdict at all. The table is now recognised structurally, header on its own line, divider immediately after, at least one row. A dead lane is also no longer counted as covered, which had made the whole failed-lane path unreachable in the one case it was written for. Repeated unanswered demands now acknowledge rather than wedge, because a stuck checkpoint is the failure this work exists to remove.

- **A head is acknowledged when its findings were read, not when its lanes exited** ([REQ-AGENT-104](agents.md#req-agent-104-review-acknowledgement-requires-a-published-verdict), new, Implemented; regression tests in `host/__tests__/enforce-review-spawn.test.js`). The checkpoint advanced on lane completion alone, which records that three processes ran rather than that anyone read them - so a round could return into a session that never triaged it while the checkpoint moved past those findings for good. It now requires the triage verdict, published after the last lane returned, recognised by its table header and divider in a message carrying no tool call; a verdict predating the evidence is not a verdict about it. Acknowledgement then drives its own fix directive, which states that the head is already acknowledged so fixing never relaunches review or CI for it. This is the contract the Pi enforcement path already ran, and both runtimes now key on the same table shape.

- **A review lane that dies no longer widens every later review** ([REQ-AGENT-102](agents.md#req-agent-102-claude-reviewer-headless-lane-transport) AC6-AC7 added; regression test in `host/__tests__/enforce-review-spawn.test.js`; rationale in [AD115](../../documentation/decisions/README.md#ad115-claude-pr-boundary-review-lanes-run-as-headless-claude--p-subprocesses)). A background lane that exits non-zero ends as failed, which the gate could not tell apart from still running. It therefore waited on a dead process, never acknowledged that head, and measured the next push's range from the last acknowledged head instead of the last reviewed one - so one lost lane permanently widened every review after it, observed as a ten-commit re-review where one commit was due. A lane that ended badly is now re-demanded at once and named in the demand, because its report can be complete enough to read like a finished round. Triage gained the byte cap its neighbouring packet already had, a missing `enforce_tdd` key no longer reads as a deliberate opt-out, and the two inlined blocks are labelled as data rather than instructions.

- **Triage is its own requirement, and a no-op is a decision rather than a substring** ([REQ-AGENT-103](agents.md#req-agent-103-deterministic-lane-triage), new, Implemented, split from [REQ-AGENT-102](agents.md#req-agent-102-claude-reviewer-headless-lane-transport) ACs 6-9; regression tests in `host/__tests__/run-review-lane.test.js`). The transport requirement had grown to nine criteria covering two separable concerns — how a lane is launched, and what it is handed. The Phase 0 work now stands on its own, which also gave the skipping decision the criterion it never had: the runner had been looking for the no-op decision anywhere in the triage document, so a reason that quoted it would have skipped a review that was owed. The decision is now read as a field. Two enforcement rules the documentation lane lost when its Phase 0 was removed — a shipped surface with no documentation page, and a missing documentation index — are restored, and the lane's evidence guidance no longer carries a call budget that could exhaust before a required sub-policy was read.

- **A review lane stops paying for context it is forbidden to use** ([REQ-AGENT-102](agents.md#req-agent-102-claude-reviewer-headless-lane-transport), new, Implemented; [REQ-AGENT-086](agents.md#req-agent-086-claude-reviewer-direct-evidence-and-root-handoff) AC1 corrected; regression tests in `host/__tests__/enforce-review-spawn.test.js` and `host/__tests__/run-review-lane.test.js`; rationale and measurements in [AD115](../../documentation/decisions/README.md#ad115-claude-pr-boundary-review-lanes-run-as-headless-claude--p-subprocesses)). A lane used to start every review already holding the whole session's instructions, memory index and rule files, none of which it is permitted to act on and none of which any per-agent setting could remove; each lane now runs in its own process carrying only its own review policy, and a lane whose range contains no file it owns returns a no-op instead of reasoning its way to one. The first acceptance criterion of the reviewer-evidence requirement was also still describing file-read and graph tools these lanes no longer carry.

- **A reviewer lane is no longer spawned to discover it owns nothing** ([REQ-AGENT-101](agents.md#req-agent-101-reviewer-lane-spawn-requires-surface-ownership), new, Implemented; [REQ-AGENT-040](agents.md#req-agent-040-pr-boundary-lane-classification-and-agent-dispatch) AC1 rewritten; regression tests in `host/__tests__/lane-classifier.test.js` and `src/__tests__/lib/review-helpers.test.ts`). Any change outside the spec and documentation trees used to demand all three reviewers. Two of them then opened, built their packet, found no file of their own in the range, and exited — each having already paid a full agent startup, which is most of what a review costs and is spent before the agent knows what it is looking at. Measured on one such push, the documentation lane spent fifty-eight thousand tokens to report that it had nothing to report. The classifier now asks the question those lanes ask first, at a point where answering it is free: a behavioural change always owes the code lane, and owes the spec or documentation lane only where that surface changed or one of its source anchors names a file in the range. A stale anchor is still caught, because an anchor naming a changed file is exactly what pulls its lane back in. Both runtimes apply the same rule, and an unresolvable repository root keeps the old all-three posture rather than guessing.

- **Renaming a rule can no longer silently push it into Pi's instructions** ([REQ-AGENT-100](agents.md#req-agent-100-pi-rule-transform-membership-validation), new, Implemented, extracted from [REQ-AGENT-014](agents.md#req-agent-014-manifest-driven-preseed-pipeline) AC4; regression tests in `host/__tests__/pi-rule-transform-membership.test.js`). Three collections name the Claude rules that Pi absorbs, compacts, or covers by a skill, and one of the three was never checked against reality. A rule renamed or merged away left a key in it that matched nothing, so the rule stopped being excluded and flowed into Pi's instruction file in full — the exact opposite of what naming it there was for, with no error and no diff to notice. Every key in all three collections is now resolved against a real rule at build time, and a key that resolves to nothing fails the build naming the file and the collection it came from. The validation was previously one clause inside a requirement about the manifest pipeline, which is why it read as covered when only two of the three collections actually were.

- **A capture is bounded by what it costs, not by how many messages it holds** ([REQ-MEM-014](memory.md#req-mem-014-pi-capture-contract-transcript-prefilter-and-model-fidelity-lever) AC5 rewritten, Implemented; regression tests in `host/__tests__/prefilter-transcript-caps.test.js` and `src/__tests__/lib/agent-seed-pi-memory.test.ts`). Capture fires on a count of the user's prompts, fifteen, while the ceiling counted messages, forty. Those are different units and the rate between them is not fixed: measured, a conversational session produces about two and a half messages per prompt and an agentic one about twenty-five. So the ceiling either sat idle or cut a fifteen-prompt window down to the last nine of its prompts, and since the prompt counter advances whether or not the slice kept everything, what it cut was never offered to a later run. It was lost, not deferred. Counting messages also prices a two-hundred-character turn the same as a ten-thousand-character one, when characters are what the payload actually costs. The ceiling is now a character budget, spent newest-first, and spent on the user's prompts before the assistant's turns: the prompts are what the window is defined by and what the trigger counted, so a payload that drops them summarises a window without the instructions that produced it. Both passes stop at the first turn that does not fit, which keeps the budget a hard ceiling even in the case where the prompts alone would exhaust it. At two hundred thousand characters, half the previous worst case, an ordinary window is untouched and an agentic one keeps around two hundred turns where forty survived. The two runtimes reach the same selection on the same input, which is verified against fixtures rather than assumed from shared prose.

- **A memory capture now costs the same whether the session is short or enormous** (no acceptance criterion changed; regression tests in `host/__tests__/prefilter-transcript-caps.test.js`). Capture fires every fifteen prompts and hands the capture agent the conversation since the last one. Nothing bounded that payload, so it grew with the session: one resumed session produced fifty chunk files from a fifteen-thousand-line transcript and cost 220,000 tokens to summarise. Chunking was already there and was the wrong instrument — it bounds how much is in front of the agent at any instant, not how much passes through it in total, and the contract requires reading every chunk in order and forbids batching them. The two ceilings Pi has always had are now applied here as well: the payload as a whole is bounded, and any single turn longer than ten thousand characters is truncated. The per-turn ceiling is measured rather than guessed: across fifteen hundred real turns the median is under two hundred characters and the ninetieth percentile is under twenty-six hundred, so ten thousand touches only the top two percent and keeps almost nine tenths of all content. Capping the payload also collapses the chunk count, which is what keeps the per-chunk pass short. Truncation is allowed to cost prose but not citations: before a long turn is cut, the requirement ids, decision-record numbers, pull-request numbers and commit hashes it contains are collected, and any that fell past the cut are appended as a short trailing line. Those are the tokens that must be verbatim and the ones a later graph query searches on, so losing them to a byte count would defeat the point of capturing at all. A turn short enough to survive intact is byte-identical to an uncapped run. Both runtimes rescue, and to the same text, so a citation kept by one is never lost by the other. One of Pi's ceilings does not port the other way: Pi also caps the capture subagent's own loop at four turns and rejects any launch request that says otherwise, and a Claude agent definition has no field that can express that.

- **The push nudge and the turn-end gate resolve the review range through one function** (no acceptance criterion changed; regression tests in `host/__tests__/gh-pr-state.test.js`). Teaching the nudge to distrust GitHub's lagging pull-request metadata left the gate still trusting it, so the two consumers of the shared lane classifier could hand it different right-hand commits and reach different answers about which reviewers a push needs. Sharing the classifier function never delivered the agreement it was written for, because agreement also requires the same range going in. That mattered more once content-based reduction landed: a wider range is not always a superset in lane terms, since a commit that changes code and a later one that reverts it leave the wider range provably inert while the narrower one is not, so the nudge could ask for one reviewer while the gate demanded three. Head resolution now lives once, beside the pull-request state helper both hooks already share. The gate uses it for the range only and still acknowledges the head GitHub reports, which is the distinction that makes this safe: acknowledging a local commit the pull request does not yet carry would skip its review entirely once it was pushed.

- **The prover now has to say it proved something** ([REQ-AGENT-040](agents.md#req-agent-040-pr-boundary-lane-classification-and-agent-dispatch) AC5 split into AC5-AC7, all Implemented; regression tests in `host/__tests__/inert-source-delta.test.js`). Withholding two review lanes rested on a program exiting zero, which meant every way of reaching the end without deciding was indistinguishable from a proof. One such way was real: the guard that decides whether the file is being run or imported compared the module's own resolved path against the raw path it was invoked with, and Node resolves symlinks for the first but not the second, so a symlink anywhere in the install path skipped the whole program and exited zero. A behavioural change would have silently lost its specification and documentation reviewers with no error anywhere. The program now prints a token when, and only when, it has actually proven the delta inert, and both classifiers require that token rather than a bare exit status; the guard resolves symlinks on both sides as well, so the two defences are independent. Two smaller corrections landed with it: a regular expression written in statement position after a closing parenthesis was lexed as a division and its body scanned as code, which now simply fails to prove rather than guessing, and the per-file git calls were hoisted into one call for the whole range, since this runs at every turn end while a pull request is open.

- **The push gate says what it means** (no acceptance criterion changed; rule prose is intentionally not pinned by tests). The rule already forbade pushing while a review was incomplete, but a later sentence in the same file said that a finding of medium severity or above "means push and re-run immediately", and read alone that licensed exactly the push the gate forbids. Three pushes went out that way in one session, each invalidating the round already running and starting another against a head nobody had finished reviewing. The gate is now stated as absolute, names that no severity or reviewer instruction lifts it, separates committing (always allowed) from pushing (once per round), and requires naming the round that closed before each push. The severity sentence now defers to it explicitly.

- **Four holes in the freshly landed lane reduction, found by reviewing it** ([REQ-AGENT-040](agents.md#req-agent-040-pr-boundary-lane-classification-and-agent-dispatch) constraint tightened; stays Implemented; regression tests in `host/__tests__/lane-classifier.test.js` and `host/__tests__/git-push-review-reminder.test.js`). Reducing a comment-only push to the code lane made a fourth lane pair reachable — an inert source delta shipped alongside a documentation change — and the push nudge had no branch for it, so it fell through to the all-three directive and asked for a specification lane the turn-end gate then silently withheld. That disagreement between the nudge and the gate is the single thing the shared classifier exists to prevent, and it was eating part of the saving the reduction was for. The prover itself had a narrower but sharper hole: it compared file contents and never looked at the file mode, so making a file executable — or swapping a regular file for a symlink — left both blobs byte-identical and was proven inert, the one case where it called a real change nothing. It now reads the mode from the raw diff and refuses any change of it. Third, `LICENSE` counted as a documentation surface to the classifier but as source to both the packet builder and Pi, so a LICENSE-only push asked for the documentation lane, whose packet then owned none of the change and exited without reviewing anything; all three now agree. Last, the Pi copy of the composable-components skill still linked to a rule that had been absorbed into the constitution and is now actively deleted from every bucket, so Pi sessions were pointed at a document that no longer exists anywhere.


- **Pi reduces a comment-only push to the code lane too, by running Claude's prover rather than a copy of it** ([REQ-AGENT-040](agents.md#req-agent-040-pr-boundary-lane-classification-and-agent-dispatch) AC5 widened to both runtimes, Implemented; the constraint recording the divergence is replaced). The content-based reduction shipped for Claude alone, and the requirement said so: Pi kept running all three lanes on a comment-only range, deliberately and fail-closed, until the scanner could be ported. Porting it would have meant a second implementation of a JavaScript lexer in a second language, kept in agreement by a parity test — which is the arrangement the plan itself called the only way two copies could be kept honest, and therefore the reason not to have two. The prover instead moves into the directory the packet builder already made canonical, which the ordinary seed transform delivers to every runtime, and Pi's classifier shells out to it exactly as it already shells out to Git. There is one scanner, so there is nothing for it to disagree with. What can still diverge is the mapping from a proven-inert delta to a lane list, because that mapping is written twice — once in shell, once in TypeScript — so a test now runs the same four ranges through both and asserts the lane lists match. The composition rule is the same on both sides: the code lane alone, plus any lane the same diff independently earns, so a comment change that also touches the specification tree still runs all three.

- **A preseed file that is retired now actually leaves the bucket** (no acceptance criterion changed; regression tests in `src/__tests__/lib/agent-seed-manifest.test.ts` and `src/__tests__/lib/r2-seed-mode.test.ts`). Seeding cleans up by deleting the keys the current build does *not* want in the active session mode, and it derives that list from the generated set — deliberately, because it never lists or scans the bucket. The consequence went unnoticed until three rules were folded into the engineering constitution: a file dropped from the manifest also drops out of the delete list, so nothing ever removes it and the container keeps loading it from a previous deploy. For a file whose content simply went away that is untidy; for one whose content moved into another file it is wrong, because the session then loads the same policy twice, once as the absorbed section and once as the stale standalone rule it was absorbed from. Retirements are now enumerated explicitly and deleted alongside the derived list, still subject to the guard that protects anything the current mode just wrote. They are applied where the deletes are issued rather than inside the derivation, because that function has an acceptance criterion of its own — it answers which keys of *this* build the current mode does not want, and a retirement is not one of them — so re-introducing a retired path later cannot delete the fresh copy. A test asserts the inverse, which is the dangerous mistake: a path listed as retired while still being seeded would be deleted immediately after being written.

## 2026-07-25

- **The engineering constitution absorbed the three rules that were really part of it** (no acceptance criterion changed; rule prose is intentionally not pinned by tests). Four separate files were loaded into every advanced session and read as one spine anyway: the constitution itself, the working principles that prevent common coding mistakes, the language-agnostic coding concretes, and the graph-first discipline. All four were already advanced-only, so merging them changed no audience — the graphify capability is still ambient across session modes while only the discipline is gated, exactly as before. The merge also closed a real gap: the constitution cited a "fix the finding, don't ask about it" rule that existed on one machine, was absent from the preseed tree, and had therefore never reached Pi or any other runtime; that policy is now a section of the constitution rather than a dangling reference. Worth stating plainly, since consolidation is usually pitched as a saving: it is not one here. Merging the three files recovered about 570 bytes, and writing down the previously undelivered findings policy spent more than that, so the unconditional instruction set grew by roughly 640 bytes. What improved is coherence and completeness, not size. Every obligation from the absorbed files was carried over, and the language-specific coding-style rules that used to extend the common one now point at the constitution's section instead.

- **A review that found only nits now ends the round instead of starting another one** (no acceptance criterion changed; rule prose is intentionally not pinned by tests). The engineering constitution told the agent to iterate until a head came back clean, with no exception for severity — so a round whose entire output was LOW findings produced a fix, a push, and a fresh three-lane review of that fix, which then found its own nits. Roughly 204,000 tokens went that way on one pull request. The rule was already severity-aware one clause earlier, requiring verification of every MEDIUM, HIGH, and CRITICAL finding and pointedly not LOW, so this completes a distinction that was half-drawn. An all-LOW result now completes the review for that head: the fixes are still written in the same session, they simply ride out on the next push that was going to happen anyway. That is batching, not deferral, and the existing prohibition on relabelling a finding to reach the LOW bucket is untouched — anything MEDIUM or above still means push and re-review immediately. Pi's constitution carries the same rule.

- **Rewording a comment no longer costs a full three-lane review** ([REQ-AGENT-040](agents.md#req-agent-040-pr-boundary-lane-classification-and-agent-dispatch) AC5 added, Implemented; one constraint replaced). The lane classifier decided which reviewers a push needs purely from the *names* of the changed files, so any file outside the specification and documentation trees meant all three lanes ran. A two-file comment-only push measured 241,870 tokens — 83% of what an eight-file one cost — to conclude nothing. Claude's classifier now also looks at the delta's *content*: when it can prove a source change is comments and whitespace, the specification and documentation lanes are withheld, because behaviour is unchanged and neither of those surfaces can have drifted. The code lane always runs. That is deliberate, and it is what makes a heuristic acceptable at all: whether a new comment is *true* is a code-review question, and a directive comment such as `@ts-expect-error` is precisely the case where a comment does change behaviour, so it still reaches a reviewer. Proving it needs a real scanner rather than a line-prefix rule, because a line beginning `//` can be text inside a template literal — true in the very file that prompted this. Both versions of the file are projected to a comment-free, whitespace-normalised form and compared, string and template bodies are copied verbatim, and a multi-line block comment is preserved as a line break because JavaScript treats it as one when inserting semicolons. Anything the scanner cannot resolve — a slash that might open a regular expression, JSX, an unterminated literal, a binary blob, an added or deleted or renamed file, an unsupported extension, or a missing runtime — is simply not proven, and the unreduced three-lane posture stands. Pi's classifier keeps running all three lanes for such a range; the divergence is one-directional and stated in the requirement.

- **Claude's pull-request reviewers now work from a scoped evidence packet instead of scanning the repository** ([REQ-AGENT-086](agents.md#req-agent-086-claude-reviewer-direct-evidence-and-root-handoff) AC1 rewritten, AC2 narrowed, AC7 and AC8 added; stays Implemented). Each lane cost 93,000 to 103,000 tokens per round and barely varied with how much had changed — a two-file comment-only round cost 83% of an eight-file one — because the reviewers pulled evidence by searching the whole repository and reading what came back. They now build their lane packet once through the shared builder and reason from its hunks and exact changed-input ranges, following a cross-lane path only where a resolved symbol actually overlaps a changed hunk rather than wherever a filename matches. With that transport in place the tools it replaces are gone: repository-wide search, indexed retrieval, graph traversal, and file mutation. Two capabilities were deliberately kept because nothing in a shell replaces them — bounded file reading, and the lookup of prior-session user preferences that lets a reviewer drop a finding the user already ruled on. Removing the write tools also settles a contradiction the definitions had carried for some time: they described writing files while their own exit checklists required that no file be written. An earlier attempt to slim these reviewers was reverted for tripling review cost; it removed the retrieval transport without putting one back, which is why this change adds the packet first and only then takes the scanning tools away. The reduced toolset applies to `/review` as well, which runs the same two agents in five places; the graph-heavy work there belongs to a separate agent that keeps every tool it had.

- **The review evidence packet builder is now one shared program instead of a Pi-owned one** ([REQ-AGENT-085](agents.md#req-agent-085-pi-reviewer-direct-evidence-transport) implementation anchors repointed and one constraint added; [REQ-AGENT-059](agents.md#req-agent-059-pi-native-review-findings-handoff) anchors repointed; both stay Implemented, no acceptance criterion changed). - **A rule that is renamed or merged can no longer leak into Pi's instructions unnoticed** ([REQ-AGENT-014](agents.md#req-agent-014-manifest-driven-preseed-pipeline) AC8 added, Implemented). Three collections in the seed generator name Claude rules by exact path in order to *exclude* them from Pi — some because the compact Pi constitution already carries their policy, some because a skill owns them, some because they become on-demand skills. Only one of the three validated its keys. For the other two, a renamed or merged rule left a key pointing at nothing, and the failure was both silent and inverted: the rule stopped being excluded and flowed into Pi's instruction file, which is the opposite of what the collection exists to do, with no error anywhere and no test that could see it. All three collections are now checked against the Claude source set before anything is generated, and a key that resolves to nothing fails the build while naming both the missing rule and the collection holding the dead key. Directory-shaped keys match by prefix, mirroring the lookup they already drive.

- **A review now covers the push that triggered it, instead of the one before** (no acceptance criterion changed; regression tests in `host/__tests__/git-push-review-reminder.test.js`). GitHub's pull-request metadata lags its own ref update, so a `gh pr view` issued milliseconds after a successful push can still report the previous head. That head became the right-hand side of the incremental review range, which meant the directive named a range ending one commit *before* the push that fired it — a delta already reviewed — while the newly pushed commit went unreviewed for that round. The hook now resolves the pull-request head and the local head separately and prefers the local one, but only when it provably contains what GitHub reported, so the range can widen and never narrow. Every other relationship keeps GitHub's value: a push of a non-current refspec, a push the remote rejected, and a concurrent push from elsewhere all leave the local head potentially *behind* the pull request, and reviewing those against a local range would silently drop commits. The turn-end enforcement hook deliberately keeps reading GitHub's head, because that is the value its acknowledgement file is compared against.

- **Opening the editor before it is ready now shows a page that eventually admits defeat** ([REQ-IDE-003](browser-ide.md#req-ide-003-ide-lifecycle-and-availability) AC3 amended, Implemented). A freshly opened IDE tab can wait on two different things, and both were mishandled. Waiting for the container to become healthy produced a JSON error body, which a bare `_blank` tab renders as raw machine text — the in-container warming page never got the chance to answer, because the Worker's health probe rejects the request before it can be forwarded. Waiting for the editor to bind inside a healthy container did show a page, but one that meta-refreshed every two seconds indefinitely, presenting a supervisor that will never arm as mere slowness. Both waits now serve an HTML page that reports elapsed time and stops with a failure state — the container-side one on a module-level clock, the Worker-side one on the episode start carried in the query string, stripped before the base-path-native server ever sees it and redirected back out of the tab's address bar once the container answers — a tab left sitting on an exhausted start would otherwise render the give-up page instantly on every later reload, a permanent failure state its own "reload to try again" could not escape. - **A long IDE chat no longer forgets what you just said** ([REQ-IDE-006](browser-ide.md#req-ide-006-ide-conversation-context-and-credential-isolation) AC5 added, Partial — unchanged by this entry, AC2 still awaits deployed Claude evidence). Each native Pi request rebuilds its prompt from scratch and replays the earlier conversation into it under a byte budget. That budget was spent starting from the *first* turn, so once a conversation outgrew it the replay carried the opening turns and was cut off before reaching the newest — the agent answered without ever seeing the message just sent, and nothing surfaced the loss. The replay is now filled from the newest turn backwards and restored to conversation order, and the budget rose from 64 KiB inside a 512 KiB envelope to 512 KiB inside 1 MiB. The transport allows 4 MiB per JSONL line, so the remaining headroom absorbs JSON escaping; past that the binding limit is the model's own context window rather than anything Codeflare sets.
