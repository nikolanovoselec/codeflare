**Finding ID:** classifier-shell-code-forms-1  (2026-08-12)
**Category:** known-limit
**Affected:** `preseed/agents/claude/plugins/codeflare-hooks/scripts/lib/boundary-classifier.cjs::boundaryOf`
**Context:** Shell wrappers now descend into `-c` and `<<<`. Two forms still classify as no-git-activity: a heredoc fed to a shell (`bash <<EOF … git push … EOF`), because `stripHeredocs` removes bodies before the scan, and a shell fed over a pipe (`printf 'git push' | bash`), whose code is not in the shell's own words at all. A third missed form, the fd-prefixed herestring (`bash 0<<<"git push"`), was closed on 2026-08-12 round 22 by widening the operator match to `/^\d*<<</`; the two declined forms above are unchanged.
**Recommendation:** Declined on 2026-08-12, deliberately and not for cost. Scanning heredoc bodies reverses a stance an existing test pins (`does not match "git push" inside echo strings`) — the same body is data when written to a file and code only when fed to a shell, and telling those apart needs the association `stripHeredocs` discards. Refusing a piped shell needs a return value meaning "unreadable code" in a contract the Stop path shares, where a false positive is a delivery reported that never happened. The gate's threat model is an agent forgetting mid-round, not an adversary evading; neither form occurs by accident. Revisit as one contract change if a third form appears — patching one spelling per round is the failure this parser was extracted to end.
