# Shared extraction: adaptive transcript trimming and owner activation

Use only the scoped `transcript_trim` tool. Call `prepare`, inspect its budget and category feedback (`inspect` rereads feedback without another heavy pass), and decide which available historical payload categories to refine. If the projected total is above 25,000,000 bytes, call `refine` with a `categories` array selecting actionable catalog entries. You may refine twice, at most three preparations total. Select categories meaningfully from measured savings and preservation constraints; do not blindly repeat an unchanged preparation. You may combine available categories. No transcript content is sent to you, and no arbitrary JSONL replacement or prose proposal is accepted.

`historical-notification-results` condenses known native, extension-authored completion result payloads and duplicate renderer previews outside the current context. It keeps correlation IDs, terminal statuses, usage, authorship and unknown fields. These notifications are not human user messages. `historical-execution-inputs` condenses recognized historical batch command payloads, keeping tool IDs, argument envelopes and unknown keys. The baseline also reduces already-permitted obsolete prose and superseded state. All actual user text, current conversation, latest authority, opaque fields, IDs, parents and accounting stay protected. Existing gaps are not repaired. Never pad or raise limits.

When `withinTarget: true`, call `activate`. The original owner rechecks its revocable authority, session, exact source prefix and branch; merges the latest ordinary append tail verbatim; atomically replaces the source; and reads back before returning. Heavy planning, reduction, validation and readback run in a low-priority independent CPU worker, not the session event loop. Only the owner may replace live history. No parent handover, native Done notification or turn-end gate is needed.

Only `committed: true` with `status: trimmed` proves verified persisted completion. Accepted total output is 15,000,000–25,000,000 bytes inclusive, with 20,000,000 preferred. Other byte counts are projections, not persisted trimmed bytes. The committed prefix includes the latest tail admitted at the owner commit fence. Readback verifies that prefix; later ordinary appends are reported separately as `currentBytes` and `appendedAfterCommitBytes`, never misrepresented as retained bytes or a raised ceiling. A committed `verification-pending` receipt permits read-only recovery, never replacement replay. Stop, abort, fork, switch or shutdown revoke uncommitted authority.

If refinement cannot safely reach the window, report the measured reason and remaining catalog savings honestly. `protected-floor-above-maximum` applies only after actionable categories are exhausted; `retained-output-below-minimum` never authorizes padding. Do not sacrifice protected state. The shared controller retains six total native attempts, suppresses pending/running duplicates and authorizes a fresh scope after a later native compaction without resetting that budget. Do not initiate native compaction or extra model completions. Do not access transcript files, shell, network, other agents, SDK/Goal internals, credentials, settings, Vault or unrelated files.
