# Vault (persistent user notes)

`/home/user/Vault/` is the persistent, user-curatable note store. It
survives sessions via rclone bisync to R2 - anything written here is
available on the next session and on every device. The vault is
always-on: tagged `user_vault` in the unified graph from entrypoint
init, never pruned by the active-repo prune-on-switch logic, and skipped
by the active-repo PostToolUse hook so a tool call inside the vault
never re-tags it.

Pair with [memory.md](./memory.md) for the chat-capture half of the
cross-session memory story; see `documentation/vault.md` for full
mechanics.

## Layout

```
Vault/
├── Index.md          <- PRESEED: codeflare dashboard (overwrite each boot).
├── README.md         <- PRESEED: vault user guide (overwrite each boot).
├── CONFIG.md         <- PRESEED: SilverBullet `#meta` config page (overwrite each boot).
├── STYLES.md         <- PRESEED: codeflare editor theme (overwrite each boot).
├── Raw/
│   ├── Sessions/     <- AGENT-OWNED: written by the capture agent (sonnet),
│   │                    one .md per 15-prompt batch. Append-only.
│   └── Pasted/       <- USER-OWNED, OPTIONAL ARCHIVE: NOT the SB drag-drop
│                        target. Move files here manually if you want a
│                        grouped attachment folder; otherwise leave empty.
├── Notes/            <- USER-OWNED: curated prose, concept notes. SB-dropped
│                        attachments land alongside the referencing note.
├── Inbox/            <- USER-OWNED: SB "Quick Note" lands under a date
│                        subfolder (Inbox/YYYY-MM-DD/). Attachments dropped
│                        on a Quick Note land in the SAME date folder.
├── Journal/          <- USER-OWNED: SB "Journal: Today" lands here.
├── Library/
│   └── Codeflare/    <- PRESEED: bundled SB plugs (pdf, treeview, github, graph).
├── graphify-out/     <- DERIVED: regenerated by the vault-extract agent (sonnet).
│                        Treat as build output; never hand-edit.
└── .silverbullet/    <- EDITOR CONFIG: SilverBullet's config + plug cache.
```

## Reading from the vault

Prefer the unified graph (`mcp__graphify__*`) for any cross-session
lookup. The graph ingests every vault file plus every active repo's
graphify-out, so a single query returns matches from the vault and
code side by side.

Use `mcp__graphify__query_graph` for free-text questions and
`mcp__graphify__get_node` when you already know the concept name. Only
read raw vault files when the graph query points you at a specific path
and you need the surrounding prose.

## Writing to the vault

| Path | Who writes | When |
|---|---|---|
| `Raw/Sessions/*.md` | The capture agent only | Triggered by the memory-capture hook every 15 user messages. Never hand-edit; the file is deterministic and re-running the agent regenerates it. |
| `Inbox/<YYYY-MM-DD>/*` (notes + attachments) | The user, via SilverBullet | Quick Note lands here. PDFs / images / other attachments dropped onto a Quick Note land in the SAME date folder (SilverBullet's drag-drop default is "next to the referencing note"). Treat the folder as user-owned. |
| `Journal/*` | The user, via SilverBullet | `Journal: Today` lands here. |
| `Notes/**/*.md` | The user, primarily | If the user asks you to file a note, write here. Use `[[wikilinks]]` for concepts; leave file paths and code symbols as prose. Attachments dropped onto a Notes/ page also land in `Notes/` next to the note. |
| `Raw/Pasted/*` | Optional manual user bucket | NOT where SB auto-routes attachments. Exists as a hand-organised archive only; if you want files there, move them manually. Do not generate files here from agent code. |
| `graphify-out/` | The graphify CLI only | Build output of `graphify extract` / `graphify global add`. Never write directly. |
| `.silverbullet/` | The editor only | SilverBullet maintains it. Touch only if you are explicitly debugging the editor. |

## Wikilink convention

- Wrap **concepts** in `[[wikilinks]]` (e.g. `[[VaultMonitorDaemon]]`,
  `[[GraphifyGlobalAdd]]`, `[[RetryWithBackoff]]`). The vault-extract
  agent emits each wikilink as a concept node with `source_file: null`,
  which is what graphify's `global_add` external-label dedup matches on
  to aggregate the same concept across vault notes and across per-repo
  graphs.
- Dedup is **exact-string label match** (case-sensitive, no
  normalisation). `[[VaultMonitorDaemon]]` collapses with any other
  concept node labelled `VaultMonitorDaemon`; it does NOT auto-link to
  a snake_case code symbol like `vault_monitor_daemon`. That separation
  is intentional - fuzzy matching would generate cross-repo noise (every
  `[[Get]]` colliding with every `get()` function). Choose PascalCase
  concept names that you actively want unified across the graph.
- Keep **file paths**, **code symbols**, and **issue/PR references** as
  prose - they namespace per-project and auto-linking them would create
  noisy cross-repo collisions.

## Things to NEVER do

- **Never `rm` from the vault.** User-curated content is sacred; if you
  think a file is wrong, ask the user.
- **Never edit `Raw/Sessions/`.** Agent-owned. Hand-editing creates
  drift between the capture agent's view and what is on disk.
- **Never write into `graphify-out/`.** Build output. Run `graphify
  extract` instead.
- **Never `cd` into the vault and run `git init`.** The vault is synced
  via rclone bisync, not git. Adding `.git/` would confuse the
  graphify-active-repo hook and the bisync filters.

## Vault-monitor hook

A second UserPromptSubmit hook (`vault-monitor-hook.sh`) picks up edits
the user makes in the vault directly. It exits 0 silently on the
overwhelming majority of prompts; when it does emit
`additionalContext`, spawn the background **sonnet** per the directive
(it reads `vault-extract-prompt.md` and runs the 5-step extraction
contract). The sonnet agent's first step is to delete the marker file,
which is the dedup gate - same protocol as the memory-capture hook.
Sonnet not haiku because vault-extract emits citations into the global
graph; haiku confabulated adjacent IDs in benchmarking, and a false
node in the cross-session graph is worse than a missing one. See AD58
for the full memory-capture rationale; vault-extract was brought under
the same bar 2026-05-18.

## Worker proxy boundary

The SilverBullet editor inside the container is reachable from the
codeflare UI through `/api/vault/:sid/`. Auth + rate-limit happens at
the Worker; the SilverBullet server itself is bound to localhost only.
Do not try to expose port 3030 directly - the auth boundary is the
Worker route.
